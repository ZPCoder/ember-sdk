# 《余烬协议》×《炉石传说》规则对照与工程约束

审计日期：2026-08-26
适用范围：`lib/game` TypeScript 权威规则引擎、Cloudflare PVP Worker、网页战斗 UI；Flutter 离线引擎另列兼容状态。

## 1. 对照口径

本项目不是《炉石传说》的换皮实现，而是以其稳定的构筑模式通用规则作为交互基线，再保留自己的 20 阵营、特质和升星机制。

Blizzard 没有发布一份覆盖所有卡牌交互的规范文档。基础规则优先引用 Blizzard 官方说明；复杂的阶段、队列和死亡顺序参考社区维护的 Advanced Rulebook。该规则书本身也明确说明它是对客户端行为的观察记录，补丁可能改变边缘交互。因此，“全部规则”在这里定义为：

1. 覆盖本项目当前卡池实际能产生的全部通用规则与关键词；
2. 列出炉石已有、但本项目数据模型尚未声明支持的结构性机制；
3. 不假装支持当前卡池没有使用的、依赖单卡脚本的特殊例外。

## 2. 术语映射

| 炉石术语 | 余烬协议术语 | 规则含义 |
| --- | --- | --- |
| Hero | 核心 | 30 初始生命；在死亡创建步骤被锁定为失败方，当前序列结束后显示结果 |
| Minion | 单位 | 占战场槽位，可攻击并承载关键词 |
| Spell | 战术 | 从手牌使用并结算效果；可被反制 |
| Mana | 法力/能量 | 永久上限通常为 10，临时能量可超出上限 |
| Hero Power | 核心能力 | 通常 2 费、每回合一次 |
| Class | 阵营 | 一副牌只能含一个非中立阵营 |
| Divine Shield | 护盾 | 抵消下一次伤害事件 |
| Deathrattle | 亡语 | 单位死亡并移出战场后结算 |
| Graveyard | 死亡历史/墓地 | 记录本局死亡的单位实体，供复活与历史条件查询 |
| Take control | 获得控制权 | 同一战场实体从当前控制者一侧移动到效果控制者一侧，不视为死亡或召唤 |

## 3. 已对齐的通用规则

### 3.1 构筑与开局

| 规则 | 炉石基准 | 当前实现 | 状态 |
| --- | --- | --- | --- |
| 牌组 | 通常正好 30 张；所有非传说牌最多 2 张、传说最多 1 张；职业牌加中立牌 | 正好 30 张；所有非传说牌最多 2 张、传说最多 1 张；单阵营加中立 | 已对齐 |
| 洗牌 | 服务器保存隐藏且预先确定的牌序 | 服务端确定性 RNG；提交列表先规范排序；镜像牌组使用不同随机流 | 已对齐并加固 |
| 先后手 | 随机决定；先手 3 张、后手 4 张并获得幸运币 | 支持随机/指定先手；3/4 张和幸运币 | 已对齐 |
| 换牌 | 可替换任意数量起手牌，随后开始首回合并抽牌 | 双方独立确认，替换牌回洗且不会立刻抽回同一物理起手 | 已对齐 |
| 幸运币 | 0 费法术，获得 1 点本回合临时法力；占手牌、计入出牌/施法与连击 | 非收藏比赛卡 `the-coin` 在换牌结束后进入通用 `hand`，拥有稳定实体、非起始牌组来源与完整费用/碎片/入手回合对齐位；可正常出牌、弃牌、复制、反制、进入墓地和免费重施放 | 已对齐当前规则 |

### 3.2 回合、资源和区域上限

| 规则 | 炉石基准 | 当前实现 | 状态 |
| --- | --- | --- | --- |
| 法力增长 | 自己首回合 1 点，每回合 +1 并补满，通常最多 10 | 相同；未花费法力不结转 | 已对齐 |
| 临时法力 | 可高于当前/永久法力上限 | 幸运币可产生 11/10；过载债务也会先吞掉临时法力 | 已对齐当前规则 |
| 手牌上限 | 通常 10；继续抽取会爆牌且不进入手牌 | 10；幸运币计入槽位；爆牌产生明确事件 | 已对齐 |
| 战场上限 | 每方 7 个战场实体 | 每方 7 个单位 | 已对齐当前卡池 |
| 满场出牌 | 单位和“仅召唤”的法术不可使用；兼有其他效果的召唤法术可使用但召唤部分可能落空 | 在扣牌/扣费前拒绝纯召唤战术和召唤型核心能力；混合效果可结算 | 已对齐 |
| 奥秘区 | 通常最多 5 个英雄区效果，且同名奥秘不可重复 | 最多 5 个奥秘，同 `secretId` 不可重复 | 已对齐当前奥秘子集 |
| 武器槽 | 同时一把；装备新武器先替换旧武器 | 相同，并生成旧武器破坏事件 | 已对齐 |

### 3.3 行动与目标合法性

- 只有当前行动玩家能执行普通指令；换牌、发现和抉择只允许对应玩家响应。
- 费用、手牌、战场、目标、潜行、嘲讽、召唤疲劳、冻结和攻击次数均在状态变更前校验；非法指令必须原子失败。
- 需要玩家选择目标的战术与核心能力在没有合法目标时不可使用；不能用 `null` 或畸形目标绕过。定向战吼是炉石式例外：场上完全没有合法目标时单位仍可入场并跳过战吼，有合法目标时则必须选择。
- 治疗可以选择满血角色，但实际治疗量为 0，也不会产生治疗事件。
- 定向敌方效果不能选择潜行单位；随机与范围效果仍可命中潜行单位。
- 纯召唤核心能力在满场时不可使用；定向核心能力没有合法目标时不可使用。

### 3.4 战斗

| 机制 | 当前语义 |
| --- | --- |
| 普通攻击 | 单位部署后有召唤疲劳；攻击力必须大于 0；攻击单位时双方伤害同时结算 |
| 嘲讽 | 存在可攻击的敌方嘲讽单位时，不能攻击其他单位或核心 |
| 冲锋 | 部署回合可攻击单位或核心 |
| 突袭 | 部署回合只可攻击单位，之后恢复普通目标范围 |
| 风怒 | 每回合最多攻击两次；冻结会消耗后续攻击机会 |
| 护盾 | 抵消完整的一次伤害事件，实际伤害为 0 |
| 剧毒 | 该单位对单位造成大于 0 的实际伤害后摧毁目标；战吼、亡语和触发伤害也保留来源 |
| 汲取 | 按该单位实际造成的伤害量治疗己方核心；对护甲造成的有效伤害也计入 |
| 激昂 | 项目自定义：受到战斗伤害并存活后 +1 攻击，最多两次 |
| 潜行 | 不能成为敌方直接目标；主动攻击后解除 |
| 冻结 | 跳过受影响单位下一次可用攻击机会，而不是简单在任意回合开始时解除 |
| 武器 | 英雄每回合攻击一次，遵守嘲讽；攻击单位时承受同时反击；每次完成攻击消耗 1 耐久 |

### 3.5 序列、触发和死亡

引擎把一次玩家行动视为一个外层结算序列，并为当前卡池实现简化的效果阶段、死亡创建、亡语队列和最终胜负检查。它遵循 Advanced Rulebook 的 Sequence / Phase / Queue 核心方向，但不是炉石完整的 Phase、不可变触发队列、优先级与 Aura Update 模型；未建模部分列在第 6 节。

关键约束：

1. 同时受到致死伤害的单位先全部锁入死亡窗口并从战场移除。
2. 同一窗口按实体入场顺序结算亡语，不按玩家编号排序。
3. 亡语造成的新死亡追加到当前死亡流程；该窗口全部亡语完成后才处理复生。
4. 复生是一次新召唤，回到 1 点当前生命，只触发一次；使用后移除活动关键词标记。
5. 变形清除原单位文字、关键词和增益，不触发死亡/亡语，也不把“替换”本身当成一次新召唤；变形后的实体获得新的入场顺序。
6. 沉默移除卡牌文字、关键词、临时增益、法术伤害和亡语，但保留当前生命值；移除正生命增益后，仅在当前生命高于新上限时截断。
7. 一个效果阶段结束并进入死亡创建时，生命为 0 的英雄会被不可逆标记为失败方；同阶段内、死亡创建前的后续治疗仍可救回英雄，之后的亡语治疗不能。已经排队的单位死亡与亡语仍会完成，并可能把另一方也标记为失败，从而形成平局。
8. Counterspell 在法术文本与过载前结算；被反制的牌仍消耗手牌和费用，但不获得过载，也不触发“施法后”效果。

### 3.6 当前卡池关键词

下列机制已经有数据字段、reducer 行为和目录契约测试，不允许只显示徽章却没有规则效果：

- 战吼、亡语、冲锋、突袭、嘲讽、护盾、汲取、风怒、剧毒、潜行、复生、冻结；
- 英雄牌、奥秘、发现、过载、连击、法术伤害、沉默、抉择、变形、可交易、预备、贿赂、伪装、破碎、先驱、巨型；
- 回合开始、回合结束、施法后触发、持续到所属玩家回合结束的临时增益；
- 项目自定义激昂和五类特质。

生成式卡池还执行以下合同：`spell-damage` 必须有非零数值；临时增益必须留有实际行动窗口；连击不能覆盖基础效果的目标；印刷描述不得承诺已被生成器覆盖掉的抽牌、伤害或增益。

### 3.7 2026 圣甲虫年扩展机制

- **预备（Prepare）**：22 张圣甲虫年 8 费牌可花光至少 1 点剩余法力，并永久降低“花费法力 + 1”的费用；每个物理手牌实例只能预备一次。减费跟随手牌槽位，交易、换牌、发现、抽牌、出牌和重复同名牌均保持对齐；AI、PVP 隐藏快照、Web 与 Flutter 都使用同一槽位语义。原第 23 张中立 8 费牌已改造成下述 10 费英雄牌，因此不再具有预备。
- **贿赂（Bribe）**：每个阵营有一张圣甲虫年贿赂战术。主效果完整结算后，对手抽 1 张牌；对手满手会按正常爆牌规则燃毁，空牌库会按正常疲劳规则受伤，被反制则主效果与交换收益都不发生。Web 权威引擎与 Flutter 离线引擎都按同一效果序列执行。
- **伪装（Disguised）**：每个阵营有一张圣甲虫年 3 费伪装单位，可由出牌者选择部署到己方或对手战场；出牌者支付费用并结算战吼/连击，接收方获得单位控制权，场地容量与同名二星升阶按接收方计算。单位在当前控制者回合结束时对其核心造成 1 点伤害，沉默可关闭该触发。Web 权威 reducer、AI、PVP 指令白名单、网页入口、Flutter 离线引擎与在线指令投影均使用同一 actor-relative `placement` 语义。

### 3.8 2026 CATACLYSM 扩展机制

- **破碎（Shatter）**：5 张猛禽年战术牌抽到或加入手牌时，按同一个物理 `groupId` 分裂成左、右两片并分别插入手牌首尾；两个片段各占一个手牌位、保留印刷费用并可独立使用各自效果。使用位于两片之间的任意卡牌后，若同组左片与右片相邻，则立即恢复为一张完整牌；嵌套碎片只先重组内层，外层仍被刚恢复的完整牌隔开。完整牌保持改造前的目标与结算语义，避免法术伤害、护盾和治疗时序回归。
- 手牌只有一个空位时只保留左片并燃毁右片；完全满手时整张牌燃毁。起手选择任意一个片段会按一张物理卡退回整组、只抽一张替代牌；交易单片则只移动被选中的手牌实例。AI 会提高“打出夹在完整碎片组中间的牌”的优先级。
- Web 权威 reducer、PVP 指令、事件回放、网页两端裂纹表现、Flutter 离线引擎、Flutter 在线快照与 AI 都使用平行 `handFragments` 槽位状态。PVP 对手只看到匿名的分裂/重组事件和手牌数量，不获得卡牌身份或 `groupId`。
- **先驱（Herald）**：6 个对齐阵营各有 2 张圣甲虫年先驱单位，共 12 张。每次使用会推进玩家公开的先驱计数，并召唤一名继承所属巨型首个附肢关键词与效果的士兵；第 2 次将当前及后续巨型、附肢和士兵强化为 ×2，第 4 次强化为 ×4，之后封顶。AI 同时持有先驱和所属巨型时会先完成宣告。
- **巨型（Colossal）**：6 张圣甲虫年巨型单位各声明一个非收藏衍生附肢。召唤会按当前先驱倍率同步缩放本体、附肢属性与附肢数值效果，并按 7 格战场上限逐个组装；本体占满最后一格时仍合法登场，但附肢数量为 0。法术召唤和复生会重新组装，变形只替换本体而不触发组装。Web、Worker 快照、Flutter 离线与联网投影均保留公开进度和衍生单位状态，收藏目录仍稳定为 1000 张。
- **英雄牌（Hero Card）**：新增 1 张原创 10 费中立传说“赤曜灭世者”。使用时保持当前生命、替换英雄身份、获得 12 点护甲，并把原核心能力替换为 2 费“残酷撕裂”（本回合 +5 攻击）；没有武器也能发动攻击，与武器同时存在时攻击力相加，但只有武器攻击消耗耐久。临时英雄攻击在所属回合结束时清零。
- **灾变（Cataclysm）**：英雄牌提供摧毁最高生命敌方单位、敌方单位范围伤害、洗入五张 1 费随机传说龙裔、召唤 12/12 龙裔四个原创分支。0/1 次先驱选择 1 个、2/3 次依次选择 2 个且不能重复，每次确认后完成该灾变的死亡创建再进入下一次选择；4 次及以上按印刷顺序在同一战吼序列自动释放全部四个，最后统一进入死亡创建。非收藏衍生龙裔不计入 1000 张收藏目录，固定费用随牌库位置移动，抽牌时转换为手牌费用状态。Web、Worker/PVP、AI、Flutter 离线与联网投影共享这套状态。

### 3.9 随从类型与类型联动

- 目录现在声明 9 类原创永久随从类型：猛兽、构装、龙裔、元素、潮裔、掠夺者、灵体、亡灵与万象。138 个单位带有至少一种类型，包含 16 个双类型与 3 个万象单位；无类型单位保持合法，非单位卡不能携带随从类型。
- 双类型单位同时响应两个类型查询；万象在规则查询时响应任意具体类型，但收藏中选择“万象”筛选仍只显示印刷为万象的单位。类型是实体身份而非卡牌文本，因此沉默不会移除，变形则以新单位身份完整替换。
- “齿隼驯养师”会使其他友方构装获得 +1/+1，验证战场类型查询、双类型、万象匹配与排除来源；“遗物估价师”从牌库检索一张构装单位，未命中不会抽取替代牌或制造疲劳，命中时固定费用覆盖仍与牌库位置同步。
- Web 权威 reducer、AI 估值、公开 PVP 战场快照、收藏筛选、卡牌/战场徽章与套牌类型分布已经对齐。Flutter 离线引擎、联网投影、收藏筛选和卡面也使用相同字段与匹配规则。牌库仍只向客户端公开数量，不因类型查询泄露隐藏顺序。

### 3.10 法术派系、定向检索与施放历史

- 目录沿用 7 类原创永久法术派系：曜术、潮术、构术、烬术、星术、森术与雷术。它们对应炉石把 Arcane、Fel、Fire、Frost、Holy、Nature、Shadow 作为永久规则标签、并用派系形成构筑和跨牌联动的设计层，但保留本项目自己的命名与阵营关系。
- `draw-spell-school` 会从牌库检索指定派系战术，命中时同步移动固定费用覆盖；未命中不会改抽其他牌或制造疲劳。“折痕战术图”现在以构术战术检索一张星术战术，使派系标签第一次参与牌库规则而不只是展示。
- 每位玩家分别保存本回合与自己上一回合成功完成施放的派系列表；重复派系保留施放顺序，条件效果按去重后的派系数判断。成功反制的战术不会进入历史，幸运币没有派系也不会伪造记录；回合交接把当前历史原子归档后清空。
- “共鸣风暴·05”会在本回合完成两个不同派系后追加抽两张牌；“共鸣符文师·02”会读取自己上一回合的两个不同派系并以战吼抽两张。AI 估值、Web/Worker 权威状态、PVP 快照、Flutter 离线与联网投影都识别这两种窗口。
- Web 与 Flutter 收藏均可按派系筛选，卡面显示派系徽章；Web 套牌工坊显示派系数量分布，双端战场会公开本回合/上回合已完成的派系历史。公开历史只含已完成施放的标签，不暴露牌库顺序或手牌身份。

### 3.11 死亡历史、复活与返回手牌

- 每位玩家分别维护公开的单位死亡历史。单位在死亡窗口从战场移除后、亡语结算前写入其当前控制者的历史，并记录原实体、卡牌身份、名称、死亡回合、全局死亡顺序与随从类型；复生后的实体以后再次死亡会形成新的记录。
- `resurrect-friendly-unit` 从最近死亡记录向前选择，可按随从类型筛选；同一次效果不会重复使用同一条记录，但历史本身不会被消耗，所以之后的复活效果仍能读取。复活体按卡牌印刷属性创建，不保留原实体的受伤、永久/临时增益、星级、沉默、冻结、攻击次数或护盾消耗状态，并作为召唤进入奥秘与巨型组装流程。
- “墓影回响·03”现在复活最近死亡的一个友方单位；“暮影折返·10”把一个敌方单位移回其当前控制者手牌。向手牌的逆向区域移动会清除战场增益，不触发死亡、亡语或死亡历史；手牌已满时返回实体燃毁。两张牌都替换了此前没有独立规则价值的生成式占位文本。
- Web 权威 reducer、AI 估值、结构化战斗事件、PVP 公开快照与墓地托盘已经接入；Flutter 离线规则、联网投影、双方墓地摘要和合同测试使用相同语义。墓地公开名称与数量，不暴露牌库或手牌。
- 6 个巨型附肢及其 6 个先驱士兵已作为 12 张非收藏对局卡登记，保留印刷属性、类型、关键词与从手牌使用时的组装效果。它们不改变 1000 张收藏数量，但现在和灾变生成龙裔一样可写入墓地、按印刷状态复活、回手并再次使用；复活本身不会触发战吼式组装效果。

### 3.12 弃牌历史、弃牌触发与找回

- `discard-random` 在当前卡已经离开手牌后，从剩余真实手牌槽位中用权威 RNG 随机选择；卡牌、费用减免与破碎片元数据会原子移除。每条公开记录包含独立弃牌实体、卡牌身份、玩家、回合、顺序与可选碎片方向，不会误写入单位死亡历史。
- 卡牌可声明 `onDiscard`。弃牌事件与历史先创建，再在原外层效果序列中结算弃牌触发；由触发造成的伤害、死亡和最终胜负仍遵守现有死亡窗口。被反制的弃牌法术不会执行弃牌，也不会制造虚假历史。
- `recover-discarded` 用确定性随机数从本局弃牌记录中无放回选择，向手牌加入印刷复制；同一次效果不会重复选同一条记录，但历史不被消耗，之后仍可再次引用。费用增益不随原手牌实体保留，破碎牌按正常“加入手牌”规则重新分片，满手则正常燃毁。
- “黑浪鱼雷”现在造成 5 点定向伤害后随机弃一张牌；“夜鳍回响·02”在使用或弃掉时随机造成 2 点伤害；“深潮潜行者·13”以战吼随机找回至多两张本局弃牌。三张牌形成可实际构筑和由 AI 估值的弃牌闭环。
- Web/Worker 权威状态、公开弃牌事件、战场历史托盘和动画已接入；Flutter 离线引擎、联网快照、双方摘要与合同测试保持同义。幸运币同样位于真实 `hand`，会被随机弃牌选中，并以同一物理实体进入公开弃牌事件和非单位墓地。

### 3.13 控制权转移

- `take-control` 永久移动指定敌方单位；`take-control-random-enemy` 用权威 RNG 从仍存活的敌方单位中选择。定向效果遵守潜行，随机效果可命中潜行；已进入待死亡状态的单位不会成为随机候选。
- 控制权变化保留同一个实体 ID、当前/最大生命、攻击、永久与临时增益、关键词、沉默、冻结、护盾消耗、星级、复生使用状态和入场顺序；只改变当前控制者与战场归属。它不创建召唤、死亡、亡语或召唤奥秘事件，之后回手会进入当前控制者手牌，死亡则写入当前控制者的死亡历史。
- 普通被夺取单位在新控制者当前回合有攻击等待；仍具有冲锋或突袭的单位按其活动关键词获得对应的即时攻击范围，冻结仍优先阻止攻击。到新控制者下个回合会进入正常刷新流程。
- 接收方战场必须有空位。定向控制战术在己方满场时会在扣牌/扣费前原子拒绝；随机控制在没有空位或合法敌方单位时不消耗 RNG、也不挤掉已有单位。随机控制亡语先完成死亡创建并释放自身槽位，因此满场亡语单位通常能用刚释放的槽位接收目标。
- “梦潮夺心”形成定向永久控制；“梦潮摄政·35”以亡语随机控制一个敌方单位。AI 会按威胁总值优先选择定向目标，并在没有接收槽位或合法目标时跳过控制牌。
- Web/Worker 权威 reducer、结构化事件与回放动画已接入；Flutter 离线引擎使用同一实体对象移动和容量语义。PVP 战场本来就是公开状态，控制事件只携带公开单位身份、前后控制者与实体 ID，不泄露手牌或牌库。

### 3.14 敌方隐藏区域复制与来源保护

- `discover-copy-opponent-hand` 从敌方当前手牌建立实体候选；卡牌身份、当前费用减免和可选破碎片方向三者相同才会去重。同名牌若费用或片面不同，会作为独立候选并用 `choiceIndex` 精确选择；超过三项时用权威 RNG 洗牌后展示三项。选择不移动或修改敌方原实体；敌方没有手牌时法术正常完成且不会开启空发现窗口。
- `copy-random-opponent-deck` 按敌方牌库的物理位置无放回随机选择，所以同名的两个实体仍可分别命中；复制不会移除、重排或修改原牌库。加入手牌的复制保留该位置当前固定费用覆盖；完整破碎牌生成独立片组，单片复制只生成对应片面并使用新片组 ID，手牌已满时按普通燃毁规则处理。
- Web 权威引擎以 `card-copied` 区分复制和抽牌，并记录 `copiedFrom` 与来源卡 ID，便于回放和审计。PVP 只向复制方公开卡牌身份、候选与最终选择；非拥有者只收到“对手复制了一张牌”的匿名事件，发现候选、选择结果和复制燃毁的牌名均被移除。普通过量抽牌/生成的燃毁消息也统一匿名，避免借共享事件旁路读取隐藏区域。
- “暗巷既视”从敌方手牌发现一张复制；“暗巷窥牌者·07”战吼复制敌方牌库中的一张随机牌；“无光窃思·12”复制两张且以无放回规则选择。AI 会按候选当前费用估值；网页与 Flutter 离线/联网界面显示相同当前费用，Flutter 离线引擎共享实体候选、破碎和燃毁语义，并以短暂来源标记区分普通发现与复制发现。

### 3.15 手牌施法历史与随机目标重施放

- 每位玩家维护按成功顺序排列的 `spellsPlayedThisGame`。它只记录从手牌完成施放的战术；被反制的战术不写入，单位效果免费施放的复制也不反过来改写“上一张使用的战术”，从而区分 play 与 cast 并避免重施放链污染查询。
- `recast-last-opponent-spell` 读取对手最后一条记录，免费施放印刷复制且不移动任何区域实体。需要目标时使用权威 RNG 重新选择当前合法角色；随机目标可命中潜行单位，没有合法目标则公开记录未结算原因而不伪造效果。
- 重施放仍进入对方法术反制窗口，继承施放者当下的法术伤害与秘契数值，结算法术派系、过载和施法后监听器。奥秘会尝试在施放者一侧暗置；发现与抉择无法等待原玩家输入，因此使用同一确定性 RNG 自动完成候选选择。它不支付原法力、不触发连击，也不加入“从手牌使用”的历史。
- “时砂回声龙”是 6 费 3/4 嘲讽单位，以战吼重施放对手上一张手牌战术。Web/Worker 产生独立 `spell-recast` 事件和回放；Flutter 离线引擎共享法术历史、随机目标、反制、派系、过载与自动选择语义，AI 只有在敌方存在法术历史时才为该战吼增加收益估值。
- PVP 不向对手投影有序法术身份历史，因为最新条目可能是尚未触发的奥秘；公开的普通法术仍由出牌事件展示，重施放真正发生时才公开被施放的非奥秘身份。该约束对应 Blizzard 曾专门修复 Asvedon 泄露奥秘的问题。
- 幸运币现在有非收藏比赛卡定义和独立实体 ID，并在双方换牌完成后作为后手的第五个通用手牌槽位加入 `hand`；旧快照的专用字段会在克隆时无损迁移，随后 `coinAvailable` / `coinEntityId` 只作为由手牌派生的兼容镜像。正常使用会作为“未始于起始牌组”的法术写入卡牌/实体历史并进入墓地，因此“上一张敌方战术”和多法术重施放都能解析其临时法力文本；被反制时只进入 `countered` 墓地，不伪造成功历史。随机弃牌和敌方手牌复制会自然命中幸运币；PVP 只向拥有者下发真实实体 ID，对手看到与该手牌位置一致的 `hidden-hand-*` 别名。

### 3.16 起始牌组来源与按来源多法术重施放

- 牌库与手牌分别用和物理槽位严格对齐的来源位标记“是否始于起始牌组”。开局 30 张牌为真；发现、敌方区域复制、弃牌找回和其他生成复制为假；生成牌洗入牌库后仍为假，抽取、定向检索、起手换牌、交易和破碎分片都随卡牌实体同步移动来源位。
- 出牌时来源位会和卡牌、费用减免、破碎片一起原子移除。成功的手牌战术把该布尔值写入与 `spellsPlayedThisGame` 对齐的历史；被反制的战术仍不写入。旧对局快照没有来源位时统一按“来自起始牌组”迁移，宁可少重放也不会把未知旧牌伪造成生成牌。
- `recast-nondeck-spells-once` 按原施放顺序重施放历史中来源为假的每一条战术记录；同名战术的不同施放记录会分别结算。每个玩家有独立的一次性标记，首次触发即消耗，即使当时没有合格战术；重施放本身仍不会追加手牌施法历史，避免递归扩张队列。
- “无垠回响议长”是 9 费 5/7 单位，以战吼每局一次重施放所有未始于起始牌组的己方法术。它与“时砂回声龙”共用随机目标、奥秘反制、派系、过载、自动发现/抉择和结构化 `spell-recast` 事件；AI 按尚未使用的一次性标记与合格历史数量估值。
- Web、Worker 和 Flutter 使用同一来源移动与保守迁移语义。PVP 即使对牌主也不发送牌库位置对应的来源位，因为真假排列会泄露生成牌在未来牌序中的位置；对手手牌来源与法术来源历史全部清空，本方只保留已经进入手牌或已完成施放的私有来源。

### 3.17 随从实体复制与跨区域重置

- Blizzard 12.0 的统一规则把牌库、手牌、战场和墓地视作有方向的区域流：场上到场上的复制保留当前增益和状态；场上到手牌是逆向复制，只保留当前卡牌身份并清除战场增益。引擎据此区分 `become-copy-of-unit`、`summon-copy-of-unit` 和 `copy-unit-to-hand`，不再把三种“复制”都退化成同一个印刷卡 ID 操作。
- 完整战场复制会保留攻击/当前生命/生命上限、关键词当前状态、随从类型、沉默、护盾、激昂、复生使用状态、冻结和永久/临时增益；复制体获得新的实体 ID、控制者、入场顺序和本回合攻击窗口。它属于召唤但不是从手牌使用，因此触发召唤后奥秘而不会再次触发被复制单位的战吼或巨型组装。
- 复制变形以刚登场的战吼来源为容器，保留该来源实体 ID 与新的入场顺序，再替换为目标的完整状态。它不是第二次召唤；对敌方单位的玩家定向复制仍受潜行保护，友方潜行单位可被己方选择。Flutter 的召唤后奥秘窗口也移动到战吼之后，确保奥秘看到自我变形的最终形态，并跳过战吼中已经死亡的单位。
- 战场复制入手只加入目标当前 `cardId` 对应的印刷定义，费用减免归零，标记为非起始牌组生成牌，不修改或移走原单位；后续重新使用时重新创建印刷状态。满场时只会召唤复制体的法术不可使用，避免先花费资源再静默跳过全部文本。
- “梦潮无面者”是 5 费 3/3，以战吼选择任意可见单位并成为完整复制；“梦潮映现”选择友方单位召唤完整复制；“镜蛇档案师”将友方单位的印刷复制置入手牌。Web、PVP 指令校验、AI 随机/主动目标、网页目标高亮和 Flutter 离线/在线入口共享 `any-unit` 与三种复制语义。

### 3.18 动态发现牌池与格式资格

- 普通发现不再把三个卡牌 ID 写死在目录里。`discover.pool` 会在选择窗口打开时，从 1,000 张可收藏牌中按当前玩家阵营或中立范围、可选牌型与对局格式实时建池；生成衍生牌、已轮转的标准牌与正在结算的来源牌不会进入候选。
- 标准对局只读取核心、猛禽年和圣甲虫年；狂野额外读取飞马年。池中至少三张不同牌时使用权威 RNG 洗牌并展示恰好三张，否则展示全部不同候选；同一 seed、格式和对局状态产生相同结果。
- 当前 31 张阵营/中立发现牌保留牌面限定范围，但都改为完整动态池。类型同时支持 `friendly + includeNeutral`，供不限定阵营的普通发现文本使用；固定 `choices` 仅保留给明确列举特殊候选的未来脚本。
- 发现牌被其他效果免费重施放时不能等待输入，会从完全相同的格式牌池中确定性随机选一张。AI 会基于实际三个候选估值；PVP 只向选择者投影候选，公开快照仍隐藏 RNG。
- `rankedFormat` 已进入 MatchState、PVP 新旧快照迁移与 AI 一次性票据。AI 奖励重放会同时核对格式并用该格式重建对局，客户端不能让演算与结算读取不同牌池。Web、Worker 和 Flutter 离线引擎共享格式、可收藏、去重、排除自身与最多三项规则。

### 3.19 手牌/牌库实体复制与附魔保留

- Blizzard 12.0 的区域方向规则明确规定：牌库到牌库、牌库到手牌、手牌到手牌与手牌到战场的复制保留附魔；手牌变形则清除法力消耗折扣。本轮把此前错误重置为印刷费用的敌方手牌复制和敌方牌库复制改为保留当前费用状态，与第 3.17 节的“战场逆向复制入手清除战场增益”形成一致的方向模型。
- 手牌复制窗口保存与候选严格对齐的实体快照，而不只保存卡牌 ID。玩家、AI、PVP 超时和 Flutter 都提交候选位置；因此两张同名牌即使费用不同，也不会因为只传 ID 而总是复制第一张。普通发现仍没有实体附魔快照，按印刷费用加入手牌。
- 费用快照只复制当下数值，不与来源实体建立引用；复制完成后双方可以独立继续变化。复制牌一律标记为未始于起始牌组。Web `card-copied` 事件记录保留的减费和可选片面，PVP 对非拥有者继续匿名，不新增隐藏信息旁路。
- 免费重施放“从敌方手牌发现复制”的效果不能停下来等待选择，会用同一物理实体池和权威 RNG 自动挑选，并保留被选实体的费用/片面。Web、Worker、网页 UI、Flutter 离线/联网投影与合同测试共享该语义。

### 3.20 Draw / Add / Copy / Overdraw 事件语义

- 炉石牌面与触发严格区分“抽牌”和“将牌置入手牌”：官方 22.0 牌面甚至在同一效果中同时使用“Whenever you draw”与“add a copy to your hand”。权威引擎因此只在牌实体真实离开牌库时产生 `card-drawn`；普通发现/生成改为 `card-added`，弃牌找回和复制继续分别使用 `card-recovered` 与 `card-copied`，不再把所有获得牌路径伪装成抽牌。
- 所有当前卡池的入手事件都携带统一 `acquisition` 来源：`draw`、`discover`、`recover`、`copy` 或普通 `add`。`discover-chosen` 只审计玩家确认的候选位置，真正进入手牌或因满手失败由对应入手/燃毁事件记录，未来添加“抽到时”触发不会被发现、复制或找回误触发。
- 实际抽牌在手牌已满时仍先从牌库移除，并产生 `card-burned`、`acquisition: draw` 与 `overdraw: true`。Blizzard 11.0 明确把这种燃毁加入公开对局历史；PVP 因此向双方展示燃毁卡牌身份。发现、生成、复制、找回或回手因满手失败时 `overdraw` 为假，非拥有者继续只能看到匿名结果，不能借燃毁事件读取隐藏选择。
- 网页回放为抽牌、生成入手、复制、找回和过量抽牌提供不同标签；过量抽牌对双方播放同一公开燃毁实体。Flutter 离线端原有抽牌、发现完成、复制与燃毁反馈已经按行为分开，联网端读取 Worker 的同一权威快照，不自行推断隐藏卡身份。

### 3.21 逐手牌入手回合与快枪

- Blizzard 对 Quickdraw 的官方定义是：卡牌在进入手牌的同一回合使用时获得奖励。因此判定必须跟随具体手牌槽位，不能只按卡牌 ID 或“本回合是否抽过同名牌”推断。
- `handEnteredTurns` 与手牌、当前费用、破碎片面和起始牌组来源逐槽对齐。起手及换牌记为 0；正常抽牌、发现、生成、复制、找回、交易替换和回手都记录当前回合。破碎卡两片自动重组时取两者较新的入手回合，以保留刚刚拿到缺失片面后的快枪窗口。
- “荒原快枪手”是可实际构筑的 3 费 3/3；若在进入手牌的回合使用，快枪抽 1 张牌。Web 和 Flutter 都生成结构化快枪触发反馈，手牌 UI 在有效窗口显示“⚡ 快枪就绪”；AI 只在具体槽位时间戳等于当前回合时计入额外效果估值。
- PVP 仅向手牌拥有者发送真实入手回合，对手的等长投影全部置 0，避免借动画或快照推断隐藏获牌时机。旧快照缺少字段时保守迁移为 0，不会凭空获得快枪奖励。

### 3.22 抽到时施放与替代抽牌

- Blizzard 12.2 将 `Casts When Drawn` 正式定义为关键词；后续针对 Prismatic Lens 的官方修复进一步说明：这类牌仍算被抽到，但不会结束在手牌。引擎因此只在牌实体真实离开牌库时检查 `castsWhenDrawn`；发现、生成、复制或找回同一卡 ID 都只会进入手牌，不会误触发。
- 自动施放会依次产生 `card-drawn` 和公开的 `card-cast-when-drawn` 事件，然后结算牌面、法术派系与“施放战术后”监听器，最后抽一张替代牌。它不占手牌槽，即使当时满手也会施放；多张连锁自动施放与最后的替代抽牌属于同一外层结算序列。
- 自动施放不是从手牌“使用”，因此不会触发反制的出牌窗口，也不写入“从手牌成功使用的上一张战术”历史；这保留了 play / cast / draw 三种事件的区别。
- “余烬埋雷”是 3 费可构筑战术，向对手牌库洗入两张非收藏的“余烬地雷”；地雷抽到时对其抽取者核心造成 3 点伤害并补抽。Web、Worker 和 Flutter 共享对手牌库插入、非起始牌组来源、自动施放反馈与替代抽牌规则。

### 3.23 牌库→手牌→单位战场的稳定实体身份

- Blizzard 12.0 的区域移动规则把牌库到手牌、手牌到战场视为同一张牌向前移动，而场上回手则只重置战场附魔。权威状态现在用 `deckEntityIds` 与 `handEntityIds` 分别和两个隐藏区域逐槽对齐：开局 30 张牌各有唯一身份；普通/定向抽牌把牌库 ID 原样移入手牌，打出单位时再把它直接变成公开战场单位 ID，不再用数组位置或卡牌 ID 冒充物理身份。
- 起手换牌会把所选手牌 ID 与费用、来源一起洗回牌库，替换抽牌保留原牌库 ID；可交易先抽取另一实体，再把被交易手牌的 ID 插回随机牌库位置。洗牌同时重排卡牌、固定费用、来源和 ID；效果洗入的新牌才创建新 ID。“抽到时施放”沿用被抽实体完成公开自动施放后销毁，不为替代抽牌误造身份。
- 单位回手时保留战场实体 ID，清除攻击、受伤、增益、沉默和攻击次数等战场状态；再次使用后仍以同一 ID 回到战场。`card-played`、`unit-summoned`、`unit-returned` 和弃牌/交易审计可据此关联同一实体，同时保证一个 ID 不会同时存在于手牌与战场。本项目特有的同名升星是合并例外：已有战场实体保留 ID，被打出的第二张手牌实体在合并中消耗。
- 破碎牌的左右片各自取得唯一实体 ID；自动重组保留左片 ID 并销毁右片身份，费用、来源和入手回合仍按既有合并规则处理。Web 与 Flutter 手牌组件以实体 ID 作为稳定 UI key，同名牌重排、移除或重组时不会错误复用组件状态。
- PVP 只向手牌拥有者下发真实手牌 ID；对手得到等长的 `hidden-hand-*` 槽位别名。牌库顺序连拥有者也不可见，因此双方快照都只收到 `hidden-deck-*` 位置别名；获牌、弃牌和交易等私密事件会删除隐藏 ID。旧快照缺少、重复或跨区域复用 ID 时会安全补齐唯一迁移值。

### 3.24 非单位卡离手后的稳定实体身份

- 成功从手牌施放的法术把原手牌 ID 写入与 `spellsPlayedThisGame` 严格对齐的 `spellsPlayedEntityIds`；同名法术不再只能靠卡牌定义 ID 区分。抉择法术在等待玩家选项期间把源实体保存在 `chooseOne.sourceEntityId`，确认后仍将同一 ID 写入历史。免费重施放是效果创建的复制，不会伪装成另一张手牌实体或改写手牌施法历史。
- 武器装备时把原手牌 ID 保存到装备槽；英雄攻击、被新武器替换和耐久耗尽事件都携带该实体 ID。奥秘进入奥秘区时保留原手牌 ID，触发事件带回同一 ID；由其他效果免费创建的奥秘取得新身份。英雄牌变身后在英雄状态的 `cardEntityId` 留存来源，灾变多选等待状态也保持相同源实体。
- PVP 中武器和英雄变身属于公开状态；敌方未触发奥秘的实体 ID 与卡牌身份一起替换成 `hidden-secret-*`，触发后才通过公开事件揭示。敌方法术身份历史及其实体 ID 都不下发，避免借历史推断仍隐藏的奥秘；牌主继续获得自己的真实记录。Web、Worker 与 Flutter 离线模型共享这些区域身份，旧法术历史缺失 ID 时生成确定且唯一的迁移值。
- 每位玩家另有按物理实体去重、按离场顺序排列的 `cardGraveyard`。普通法术结算或被反制、抽到时施放、非单位卡被弃或因满手燃毁、武器被替换或耐久耗尽、奥秘触发、英雄牌完成变身都会以原实体 ID 写入，并记录来源区域、离场原因、回合和顺序；同名卡可独立查询，重施放复制不会污染实体墓地。抽牌燃毁保留牌库实体 ID，发现/复制等未能入手的卡先分配独立生成实体；PVP 对手快照不下发私密墓地明细，公开反馈仍只由既有出牌、触发、替换、损毁与过量抽牌事件承担。
- Web 与 Flutter 已共享当前非单位卡的区域身份和墓地语义；单位死亡仍使用包含控制者、随从类型和死亡顺序的专用 `deathHistory`，弃牌检索仍使用含碎片方向的 `discardHistory`。未来若卡牌需要跨所有类型查询完整区域轨迹，还需把项目特有的升星/碎片合并等终止路径与两个专用历史汇总为只读查询层，该更高层差距仍列于第 7 节。

### 3.25 胜负、疲劳和最长对局

- 核心在死亡创建步骤被锁定为失败方，并在当前外层结算序列完成后显示结果；序列中双方都被锁定为失败时判平局。
- 投降立即让对手获胜。
- 空牌库后每次尝试抽牌承受递增的 1、2、3……点疲劳伤害，先扣护甲。
- 完成第 89 个玩家回合后，不开启第 90 个行动窗口，直接平局。
- PVP 主阶段、换牌、发现和抉择都有服务端默认超时动作；当前 Cloudflare 实现由下一次房间请求触发检查，尚不是独立墙钟唤醒。

## 4. 服务端权威与隐藏信息

这些不是牌面关键词，但属于线上卡牌游戏规则的一部分：

- PVP Worker 重建严格白名单指令，玩家编号来自会话角色，客户端不能自报身份。
- `commandId` 按玩家分域，重复提交幂等；对手复用同一字符串不会得到成功空操作。
- 服务端快照隐藏双方牌库顺序、随机种子和 RNG 状态；对手手牌只暴露数量，事件也会移除种子与隐藏牌名。
- 破碎片的牌名、片段方向和 `groupId` 只在拥有者快照中可见；对手快照使用等长空标记，分裂/重组事件也会匿名化。
- 敌方手牌发现的候选与最终选择只对发现方可见；`card-copied`、`card-burned` 对非拥有者删除牌名与隐藏候选，只保留发生了复制或燃毁这一公开事实。
- 有序法术身份历史只保留在服务端与本方快照；对手快照清空该数组，避免通过“上一张法术”字段识别尚未触发的奥秘。
- 牌库来源位对双方都替换为等长保守标记，不能据此预测生成牌插入位置；对手手牌来源位与按来源施法历史清空或等长匿名化。
- 牌库实体 ID 对双方（包括拥有者）都替换成随当前位置生成的匿名别名；对手手牌也只收到位置别名，只有本方手牌可读取真实稳定 ID。
- 行动时钟只在新的行动窗口开始时重置，普通指令或重复指令不能续时。
- PVP 开局以条件写入创建唯一 `matchToken`，并绑定不可变的 host/guest 身份；同身份自匹配、并发双开、活跃决策阶段覆盖和绕过 rematch 均被拒绝。
- PVP 战报不采用客户端声称的座位、胜负或模式；服务端按参赛身份和终局快照推导。离场按投降结算，终局快照会归档到双方都完成记账之后；登录或主动归档会幂等补记遗漏战报。因此败方关闭页面也不能逃避失败记录；Casual 只记战报与通用进度，不改变天梯。
- AI 开局由服务端签发并持久化一次性票据，固定 seed、先后手、标准/狂野格式、已保存且拥有的卡组和对手原型；未消费票据会恢复而不是重抽随机参数。结算时服务端用同一格式与策略重演 AI 换牌、发现、目标与完整回合，并在玩家状态、奖励、战报、审计同一 D1 batch 内原子消费票据；换幂等键重领、伪造格式、伪造 AI 投降、漏行动或改目标均拒绝。
- 洗牌、发现和 AI 决策使用可复现 RNG，便于回放；公开快照不携带可预测未来牌序的状态。

## 5. 明确保留的项目差异

这些行为不是炉石规则，必须作为产品特色保留并在 UI 中明确：

1. **同名升星**：再次使用同名单位会把场上单位升为二星，而不是部署第二个单位；满场仍允许升星。
2. **五类特质**：迅锋、坚阵、秘契、猎痕、巧铸按不同单位数量形成 2/4 档联动。
3. **20 阵营**：取代炉石职业；每个阵营有独立核心能力，但当前大量阵营复用伤害、抽牌、护甲或治疗模板。
4. **激昂**：本项目的受战斗伤害成长机制，不等同于炉石历史关键词 Enrage。
5. **秘契特质**：会统一放大战术的伤害、治疗和增益数值，这是项目全局规则，不是炉石的 Spell Damage。

## 7. 尚未建模的炉石结构

当前卡池没有依赖这些机制，因此它们不是现有卡牌的静默 bug；若未来加入相应卡牌，必须先扩展状态模型和测试，不能只新增关键词文本。

| 缺口 | 所需模型/规则 |
| --- | --- |
| Location、Dormant、Titan 等实体类型 | 新区域/槽位、耐久或能力冷却、目标与入场序列；英雄牌与巨型附肢已由当前状态/召唤序列覆盖 |
| Quest、Questline、Sidequest、Sigil、Objective 等英雄区卡 | 独立英雄区实体、进度、延迟触发、公开/隐藏状态与区域上限 |
| Aura 与复杂 enchantment 分层 | 持续重算、时间戳/入场顺序、来源离场后的属性回滚 |
| 完整 Phase、不可变触发队列与优先级 | 更细的 Play/Spell/Combat/Trigger Phase、Aura Update、通用 pending-destroy、英雄替换例外，以及所有跨 Phase 的死亡创建规则 |
| 战场位置相关效果 | 可选择插入战场位置、相邻单位与战场移动语义；手牌两端/相邻语义已由破碎机制覆盖 |
| 直接偷取敌方手牌/牌库卡牌 | 复制已有独立事件、实体费用快照与隐藏候选语义；直接偷取仍需原子移动实体、费用覆盖与双方可见性规则，战场永久/随机控制权转移已覆盖 |
| 英雄冻结、免疫和武器关键词 | 扩展 `HeroState` / `WeaponState` 及攻击合法性；英雄临时攻击已覆盖 |
| 英雄技能刷新、动态费用与多次使用 | 可叠加的技能状态、次数上限、刷新历史；英雄牌直接替换技能已覆盖 |

Flutter 离线引擎应被视为便携练习模式；正式 PVP 必须使用发布网页的 D1 轮询传输和 Worker TypeScript 权威状态。Flutter 现有 WebSocket 页仅作本地协议调试，不具备身份绑定、终局归档和正式排位结算能力。Flutter 每次新增离线规则时都需要对应的跨引擎合同测试，避免再次出现硬币、同时伤害或武器反击不一致。

## 8. 规则变更的合并门槛

以后每个规则变更都必须满足：

1. 非法动作原子失败：状态、费用、手牌、RNG 和版本均不改变。
2. 隐藏信息不进入非拥有者快照、日志消息或动画 payload。
3. 同一 seed、同一牌组多次重放得到完全相同结果；不同玩家的镜像牌组不共享牌序。
4. 卡牌描述、关键词、字段和 reducer 行为有目录级合同测试。
5. 同一行动内先完成效果与触发，再进入死亡窗口，最后检查英雄胜负。
6. 新增实体类型或关键词前，先定义区域、目标、时序、沉默/变形/复制/死亡交互和客户端隐藏策略。
7. 至少通过游戏规则测试、完整 Web 构建、ESLint 和 Flutter 测试；PVP 变更还需覆盖服务端快照与权限测试。
